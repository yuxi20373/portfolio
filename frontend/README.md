# Knowledge Chatbot - Frontend

A single-page app built with Vue 3, loaded straight from a CDN - no
bundler, no `node_modules`, no build step for local dev. Deploys
independently on **Vercel**; talks to the backend (deployed separately on
Render) over HTTP.

## Architecture

```
frontend/
├── index.html                  # SPA shell
├── build.js                     # Vercel-only: writes API_BASE_URL into config.js
├── package.json                  # just enough for Vercel to run build.js
├── vercel.json                    # buildCommand/outputDirectory for Vercel
└── assets/
    ├── css/style.css            # includes light/dark theme variables
    ├── images/                   # your own PNGs go here - see images/README.md
    └── js/
        ├── config.js              # window.API_BASE_URL (generated by build.js on Vercel)
        ├── app.js                 # root component, mounts the app
        ├── store.js               # shared reactive state + actions (incl. theme)
        ├── api.js                 # fetch wrapper, prefixes requests with API_BASE_URL
        ├── icons.js / markdown.js
        └── components/
            ├── Sidebar.js         # icon nav (incl. Home) + search + sessions + wiki folders + mini calendar
            ├── HomeView.js        # themed landing page: hero image + floating clickable images
            ├── ChatView.js
            ├── WikiView.js        # entry detail, manual edit, delete, Search panel, Adjust trigger
            ├── AdjustDrawer.js    # right-side propose-then-confirm panel for wiki edits
            ├── DrawerShell.js     # shared resizable right-side drawer chrome
            ├── CalendarView.js    # month grid + day detail + notes (add/edit/delete) + weather widget
            └── MiniCalendar.js
```

## Local dev

No install step - just serve the folder statically and point it at a
running backend.

```bash
cd frontend
python -m http.server 5500   # -> http://localhost:5500
```

By default `assets/js/config.js` has `window.API_BASE_URL = ""`, meaning
requests go to whatever origin served the page. If your backend runs on a
different port locally (e.g. `python run.py` on :8000 while this serves on
:5500), either:
- open `frontend/index.html` directly and edit
  `assets/js/config.js` to `window.API_BASE_URL = "http://localhost:8000";`
  for local testing (don't commit that change), or
- just serve both from the same origin/proxy.

## Deploying on Vercel

1. Push this repo to GitHub/GitLab.
2. Vercel dashboard -> **Add New** -> **Project** -> import the repo.
3. Set **Root Directory** to `frontend`.
4. Framework preset: "Other" (Vercel should pick up `vercel.json`
   automatically, which sets the build command to `npm run build` and
   output directory to `.`).
5. Add an environment variable: `API_BASE_URL` = your Render backend URL
   (e.g. `https://knowledge-chatbot-backend.onrender.com`) - **leave this
   blank until the backend is deployed and you have that URL.**
6. Deploy. `build.js` runs during the Vercel build and writes
   `API_BASE_URL` into `assets/js/config.js`, which the whole app reads
   from at runtime.
7. If you change `API_BASE_URL` later, trigger a redeploy (env var changes
   don't take effect until the next build, since it's baked in at build
   time, not read at request time).

## Notes

- **Home page images**: the landing page (`components/HomeView.js`) looks
  for PNGs in `assets/images/` (`hero.png`, `icon-light.png`,
  `icon-wiki.png`, `icon-calendar.png`, `icon-weather.png`) and falls back
  to plain SVG icons for anything missing, so the page never looks broken
  before you add your own artwork. See `assets/images/README.md` for exact
  filenames/sizes.
- **Dark mode**: toggled by clicking the floating button at the top of the
  home page's hero image (`store.toggleTheme()`), persisted to
  `localStorage`, applied via a `data-theme="dark"` attribute on
  `<html>` that flips the CSS variables in `style.css`.
- No dependencies at all, on purpose - `build.js` only uses Node's builtin
  `fs`/`path`. If you ever want to add a real bundler, this is a natural
  point to introduce one, but it's not required for anything here to work.
- `marked` and `DOMPurify` (Markdown rendering) and Vue itself are loaded
  as plain `<script>` tags from CDNs in `index.html` - if you need to pin
  versions or self-host them, that's the place to change.
